# Google Play 등록 적합성 검토

작성: 2026-11-03. 코드 변경 없이 저장소의 실제 설정과 빌드 결과(0.1.12 이후 `master`)를 기준으로 판단했다. 실기기 확인은 아직 하지 않았다.

## 결론

기능과 정책 면에서는 **등록할 수 있는 앱**이다. 위험한 권한이 없고, 데이터를 수집하지 않으며, 네이티브 라이브러리도 없다. 다만 지금 상태로 바로 올릴 수는 없다. 아래 "반드시 할 일"(서명된 AAB, 앱 아이콘, 오픈소스·HWP 출처 표시, 개인정보처리방침, 실기기 확인)을 끝내야 한다. 개인 개발자 계정이라면 비공개 테스트 기간도 필요하다.

## 이미 충족된 것 (확인함)

| 항목 | 현재 상태 | 근거 |
|---|---|---|
| 대상 API | `targetSdkVersion 36`, `compileSdk 36`, `minSdk 24` | `android/variables.gradle`. 새 앱 기준(API 35 이상)을 넘는다. |
| 권한 | `INTERNET` 하나뿐(Capacitor 기본) | `AndroidManifest.xml`. 저장소 권한(`MANAGE_EXTERNAL_STORAGE` 등) 없이 SAF로 파일을 연다. 권한 심사 대상이 아니다. |
| 16KB 페이지 크기 | 해당 없음 | APK에 `lib/*.so`가 없다(HWP 해석기도 WebAssembly). |
| 데이터 수집 | 없음 | 서버로 보내는 것이 없다. 기록은 기기 안에 저장한다. 기록 옮기기는 사용자가 만든 파일로만 한다. |
| 광고·결제 | 없음 | |
| 앱 ID | `com.mins.epubviewer` | 바꿀 수 없으니 그대로 쓴다(이름은 Mins Reader). |

## 반드시 할 일 (등록 전)

1. **배포 서명과 AAB.** (2026-11-03 완료: `npm.cmd run release:aab`, 키는 `android/keystore/`(git 무시), doc/ANDROID.md "Play 스토어용 AAB") 지금 APK는 디버그 서명이고, Play는 AAB(`bundleRelease`)를 요구한다.
   - 업로드 키를 만들고 Play App Signing을 쓴다. 키는 Git 밖에 보관한다(AGENTS.md 규칙).
   - `scripts/release.cjs`에 AAB 빌드를 추가한다.
   - 기존 디버그 설치본과는 서명이 달라서 업데이트로 설치되지 않는다. 테스트 사용자에게 미리 알린다.
2. **앱 아이콘.** (2026-11-03: 스토어 아이콘·그래픽 이미지는 `doc/store/`에 만듦. 런처 아이콘 교체와 스크린샷은 남음) 런처 아이콘이 Capacitor 기본 아이콘(파란 X)이다. 스토어용 512×512 아이콘, 1024×500 그래픽 이미지, 휴대폰 스크린샷(2장 이상)도 필요하다.
3. **오픈소스 고지 화면.** 앱에 넣은 라이브러리와 글꼴의 라이선스를 앱 안에서 볼 수 있어야 한다. 대상:
   - PDF.js(Apache-2.0), docx-preview(Apache-2.0), epub.js(BSD), mammoth(BSD), JSZip, pako(MIT), Toast UI Editor(MIT)
   - hwpjs hwp-core(MIT), 나눔고딕·나눔명조·Noto Sans Symbols 2(OFL), PDF.js 표준 글꼴(Foxit·Liberation)

   지금은 라이선스 파일만 들어 있고 화면은 없다. Apache-2.0은 고지를, OFL은 라이선스를 함께 배포할 것을 요구한다.
4. **HWP 공개 문서 출처 표시.** 한컴의 HWP 공개 문서는 이를 참고해 만든 제품에 "본 제품은 한글과컴퓨터의 한/글 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."를 표시하도록 조건을 둔다(hwpjs README에도 같은 문구가 있다). 앱 정보 화면과 스토어 설명에 넣는다. 원문 조건은 등록 전에 한컴 사이트에서 다시 확인한다.
5. **개인정보처리방침 URL과 데이터 보안 양식.** Play Console의 "앱 콘텐츠"에서 요구한다. 수집이 없다고 적는 짧은 페이지면 된다(GitHub Pages 등).
   - 데이터 보안 양식: "수집·공유 없음".
   - 열린 링크가 외부 브라우저로 가는지는 실기기에서 확인한다.
6. **실기기 확인.** 몰아서 하기로 한 항목들과 함께 확인한다.
   - 큰 HWP·PDF에서 메모리 부족이나 앱 멈춤(ANR)이 없는지
   - 다른 앱에서 열기·공유받기
   - 화면 회전, 백그라운드에서 돌아온 뒤 복원

   Play 사전 출시 보고서(자동 기기 테스트)도 참고한다.
7. **(개인 개발자 계정이면) 비공개 테스트.** 2023년 11월 이후 만든 개인 계정은 프로덕션 공개 전에 테스터 12명 이상이 14일 이상 비공개 테스트를 해야 한다. 계정 종류와 현재 조건은 Play Console에서 확인한다.

## 권장 (등록에 필수는 아님)

- **자동 백업 범위.** `android:allowBackup="true"`라서 앱 내부에 복사한 문서(최대 512MB)까지 Google 자동 백업 대상이 될 수 있다. 백업 한도는 25MB다. `dataExtractionRules`/`fullBackupContent`로 문서 사본은 빼고 읽기 기록만 백업하면 개인 문서가 의도치 않게 올라가는 것도 막는다.
- **열기 목록 범위.** `application/octet-stream`, `application/zip`, `text/plain`까지 받아서 거의 모든 파일의 "다른 앱으로 열기"에 앱이 나온다. 정책 위반은 아니지만 사용자가 혼란스러울 수 있다. 실제로 필요한 형식만 남길지 검토한다.
- **상표 표현.** "한글", "HWP"는 한컴의 상표다. 스토어 제목과 설명은 "HWP 파일 보기 지원"처럼 기능을 설명하는 표현으로 쓰고, 한컴과 관련된 앱처럼 보이지 않게 한다.
- **콘텐츠 등급 설문.** 사용자 파일을 보여 주는 리더라서 일반 등급이 예상된다(사용자 간 공유 기능 없음).
- **난독화.** `minifyEnabled false`. 앱 대부분이 웹 자산이라 효과는 작다. 필요하면 R8만 켠다.
